# 오디오 → MIDI 설계 (2026-11-19)

WAV 등을 열면 음을 읽어 MIDI로 바꾸는 기능(devlog v0.3-10)을 고도화하기 전에, 무엇이 왜 틀리는지 재고 방향을 정한 기록이다.
숫자는 모두 샘플팩 루프 90곡(같은 이름의 wav · mid 짝, mid를 정답으로, 시작점 ±50ms)에서 잰 것이다 — `python -m eval.transcribe`.
실험 스크립트는 저장소에 넣지 않았고, 결론과 숫자만 여기 남긴다.

## 목표

샘플 루프(8~60초, 신스 · 피아노 · 패드 · 보컬 찹, 효과 많음)를 열면 **바로 편집에 쓸 수 있는 MIDI** — 템포가 맞고, 음이 격자에 맞고, 코드 진행이 맞는 것.
음 하나하나를 정답과 똑같이 받아 적는 것은 목표의 일부일 뿐이다(아래 진단상 지금 쓸 수 있는 모델로는 한계가 뚜렷하다).

## 진단

모델 출력(음마다 · 칸마다 활성도)을 한 번 저장해 두고, 단계마다 어디서 잃는지 쟀다.

| 무엇 | 완성 루프 | 정답과 가장 맞는 stem |
| --- | --- | --- |
| 정답 음이 모델 활성도에 켜져 있음 (옥타브 무시) | 91% | 94% |
| 같은 음 높이로 켜져 있음 | 57% | 64% |
| 음표로 묶은 뒤 정답 음을 찾음 (재현율, 중간) | 15% | 15% |

- **악기 분리를 해도 재현율이 그대로다** — 정답 악기만 따로 담긴 stem(완벽한 분리)에서도 15%. 분리는 지금 우선순위가 아니다.
- 놓친 정답 음 2665개의 이유: 다른 옥타브에서만 들림 26% · 다른 옥타브로 잡음 25% · 모델이 못 들음 26% · 시작점이 50~250ms 어긋남 12% · 활성도는 있는데 음표가 안 됨 9%.
  - 옥타브 오류는 대부분 음마다 생기는 모델 오류다. 파일 전체가 통째로 옥타브 옮겨진(신스 패치가 옮겨 울리는) 곡은 61곡 중 10곡뿐.
- 더 생긴 음 4304개: 울리는 중인 음을 또 잡음(쪼개짐 · 잔향) 26% · 배음(5도 · 옥타브 위) 26% · 옥타브 다른 음 15% · 시작점 어긋남 13%.
- 맞은 음의 시작점 차이는 중간 +13ms — 체계적인 늦음은 작다.
- 정답 mid는 대부분 16분 격자에 맞춰져 있다(곡 중간 100%, 90곡 중 56곡이 90% 넘게).
- **코드 수준으로는 꽤 맞는다** — 박마다 코드 근음이 정답 mid와 같은 비율 중간 75%(완성 루프 · stem 모두). 음표 F1(0.2 안팎)과 전혀 다른 수준이다.
- 템포: 90곡 모두 길이가 정확히 정수 마디다. 그런데 예전 규칙은 4 · 8 · 16마디(2의 거듭제곱) 곡도 17곡을 틀렸고(격자 점수가 맞는 길이 템포를 뒤집음), 12 · 24마디는 후보에 없었다.

## 결정

| # | 결정 | 근거 |
| --- | --- | --- |
| 1 | 음 인식 모델은 **Basic Pitch 유지** | 코드 · 가중치 라이선스가 모두 허용적이고 CPU · ONNX로 바로 도는 후보가 이것뿐 (아래 표) |
| 2 | 악기 분리는 **하지 않는다** | 완벽한 분리(stem)에서도 재현율 그대로 · 분리 모델 가중치 라이선스가 대부분 불분명 · CPU에서 느림 |
| 3 | 템포 짐작을 **새로 짠다** | 정수 마디 후보 + 자유 템포(첫 박 위치 포함) 중 박 · 뒷박 · 16분 자리에 시작점이 몰리는 것, 90~180 BPM으로 접기 → 정확 51 → 77/90 |
| 4 | ~~음표 정리를 다듬는다~~ → **넣지 않음** | 시작점 문턱 0.6은 stem F1을 A · B 모두 올리지만(0.26 · 0.28 → 0.28 · 0.32) 섞인 루프의 재현율 · 코드 근음을 깎는다(중간 0.15 → 0.11 · 0.75 → 0.70). 사용자가 주로 여는 건 섞인 루프다. 쪼개진 음 합치기 · 같이 시작한 배음 빼기는 문턱 0.5에서 효과 없음(stem F1 −0.001 · +0.006) |
| 5 | 음이 대부분 박에 붙어 있으면 **격자에 맞춘다** | 정답 mid가 격자에 맞춰져 있고 편집 · 에이전트 명령이 쉬워진다. 시작점의 60% 이상이 이미 16분 격자 ±0.25칸 안인 파일만 — 스윙 · 셋잇단 · 틀린 템포는 이 검사에 안 걸린다. 점수는 그대로 |
| 6 | 템포를 직접 넣을 수 있게 한다 | 이름에 BPM이 없으면 짐작이 틀릴 수 있다(새 규칙으로도 90곡 중 13곡 반/두 배 · 틀림) |
| 7 | **코드 진행 트랙**은 들어 보고 정한다 | 코드 근음 75%는 음표보다 훨씬 쓸 만하지만, 결과 모양(트랙 하나 더 · 바꿔 넣기)은 귀로 정할 일 |

## 단계

1. **템포 + 평가 고도화** — 평가에 코드 근음 일치 · 평균 · A/B 묶음 · 루프가 아닌 녹음(앞뒤를 잘라 다시 바꾸기) 템포를 넣는다. 목표: 정확 70/90 이상, 틀림 10 이하.
   → 완료(v0.3-11): 정확 **77** · 반/두 배 8 · 틀림 **5**, 끝 자름 75 · 앞 자름 76. 루프가 아니면 짐작한 첫 박 위치만큼 음을 밀어 박에 맞춘다.
2. **음표 정리 + 격자 맞춤** — A/B 두 묶음 모두에서 stem F1이 오를 때만 넣는다. 격자 맞춤은 이름 · 직접 넣은 템포일 때만.
   → 완료(v0.3-12): 음표 정리는 섞인 루프에서 손해라 넣지 않았다(결정 4). 처음엔 stem 평균만 보고 넣었다가, 실제 평가에서 섞인 루프 중간값이 떨어진 걸 보고 뺐다 — 이제 stem · 섞인 루프 · 코드를 함께 본다.
   격자 맞춤은 템포 출처와 상관없이 "대부분 격자에 붙은 파일"이면 한다(90곡 중 32곡, 점수 그대로).
3. **템포 입력** — 이름에 BPM이 없는 오디오를 열 때 템포를 물어본다(모르면 비워 두면 짐작).
   → 완료(v0.3-12): 열 때 작은 창으로 묻고, "모르겠어요"면 짐작. 이름에 BPM이 있거나 MIDI면 묻지 않는다.
4. **코드 진행 트랙** — 들어 보고 정한다.
5. 보류: Harmonica 공개 시 교체 시험 · MR-MT3 시험 · Spleeter(완성곡에 보컬 · 드럼이 섞인 경우).
